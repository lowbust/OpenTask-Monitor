# OpenTask Monitor

**Версия 0.3.0 · Windows 10/11 x64 · MIT**

Локальный диспетчер процессов, служб и автозагрузки с инструментами анализа памяти,
системными снимками и журналами. Интерфейс на русском языке, тёмная тема, ручное
управление опасными операциями. Установка Python для запуска готовой программы не нужна.

> Приложение не является антивирусом, EDR или песочницей. Результаты анализа —
> основания для ручной проверки, а не диагноз заражения или гарантия безопасности.

## Скачать и запустить

| Файл | Содержимое |
|---|---|
| `OpenTaskMonitor-0.3.0-windows-x64-portable.zip` | Один `OpenTaskMonitor.exe` |
| `opentask-monitor-0.3.0-source.zip` | Исходный проект, тесты, документация и сборочные скрипты |

1. Распакуйте EXE из portable-архива в обычную папку.
2. Запустите `OpenTaskMonitor.exe`.
3. При первом запуске дождитесь подготовки встроенных компонентов. Интернет не нужен.

Библиотеки распаковываются в
`%LOCALAPPDATA%\OpenTaskMonitor\packages\<версия-хеш>` и используются повторно.
Для первого запуска нужны несколько сотен мегабайт свободного места. Рядом с EXE
папка runtime не создаётся. Однофайловая поставка не означает отсутствие файлов в профиле.

Программа не запрашивает повышение прав автоматически. Доступ к чужим процессам,
службам и HKLM может требовать запуска от администратора; даже это не открывает все
защищённые процессы. Не отключайте антивирус или SmartScreen ради запуска.
Собственный EXE не имеет цифровой подписи.

## Основные вкладки

- **Процессы:** CPU, RSS, потоки, пользователь, путь, PPID и признаки для проверки.
  Поиск, CSV, свойства, дерево, приостановка/возобновление и подтверждаемое завершение.
- **Службы:** просмотр и ручной start/stop с обычными правами Windows.
- **Автозагрузка:** Run/RunOnce с резервной копией перед отключением;
  Startup folders и задания планировщика — просмотр.
- **Система:** сведения об операционной системе и оборудовании.
- **Журнал:** сообщения и действия приложения.

Изменения опасного характера требуют подтверждения с ответом по умолчанию «Нет».
Denylist и PID/create_time снижают риск ошибки, но не являются полной защитной границей.
Кнопка «Приостановить» над таблицей ставит на паузу сбор данных, а не процессы.

## Новое в 0.3.0

- Read-only сравнение исполняемых секций главного PE-образа с EXE на диске,
  учёт ASLR relocations и исключение IAT, private executable-регионы и адреса старта потоков.
- Анализ привилегий токена, elevation/integrity и выделение включённых чувствительных прав.
- Объяснимый приоритет проверки 0–100, подсветка и отключаемое закрепление сверху.
- JSON-снимки системы, сравнение изменений и фильтр новых EXE.
- Карантин в проверенном ZIP-контейнере до завершения процесса и удаления исходного EXE.
- Наблюдение за hosts/DNS/выбранными IFEO-записями, просмотр Windows/Sysmon и NVIDIA NVML.
- CSV дополнен путём EXE, приоритетом и объяснением баллов.

Новые мониторы выключены по умолчанию. Тяжёлые проверки выполняются в фоне по запросу,
а не добавляются к каждому обновлению основного списка процессов.

## Анализ выбранного процесса

Выберите процесс и нажмите **Анализ…** или откройте анализ через контекстное меню.

| Раздел | Что делает | Границы |
|---|---|---|
| Подпись / VirusTotal | Offline Authenticode и существующий отчёт VT по SHA-256 | Нет online revocation и upload файла; доверенная подпись/0 detections не гарантируют безопасность |
| Process Tree | Дерево по PPID с проверкой времени создания родителя | Снимок может устареть; необычный родитель — подсказка, не диагноз |
| DLL | Read-only список доступных загруженных DLL | Не полный поиск скрытых модулей и не доказательство injection |
| Сеть | IPv4/IPv6 TCP/UDP, адреса, порты, обновление выбранного процесса | Разрыв только IPv4 TCP с нужными правами; процесс может переподключиться |
| Дескрипторы | Доступные File/Key handles через изолированный helper | До 512 записей/10 с; оригинальные handles не закрываются, список частичный |
| Память / потоки | Сравнение кода главного PE, private executable-регионы, адреса старта потоков | До 15 с; не все DLL/JIT/Python и не все скрытые потоки; отличия могут быть легитимными |
| Права токена | Privileges, elevation/integrity, выделение чувствительных прав | Ничего не включается/отключается; необходимость прав автоматически не определяется |

У сравнения памяти учитываются HIGHLOW/DIR64 relocations, IAT исключается.
Непрочитанные байты и ограничения отражаются в отчёте. Hotpatching, JIT,
инструментирование и защитное ПО могут давать легитимные отличия.
Полная матрица пределов: [docs/SECURITY-ANALYSIS.md](docs/SECURITY-ANALYSIS.md).

## Приоритет проверки

Столбец **Приоритет 0–100** находится справа в таблице процессов. Подсказка при
наведении объясняет слагаемые. Строки от 60 баллов выделяются красным; закрепление
сверху отключается в меню «Инструменты». Приоритет и причины включены в CSV.

Это не вероятность заражения. Неизвестная или недоступная подпись не считается
отсутствующей, public/unknown IP сам по себе баллов не даёт. Высокий приоритет
может быть у легитимных установщиков, инструментов разработчика и администрирования.
Нулевой приоритет не подтверждает безопасность.

## Снимки и системное наблюдение

Откройте **Инструменты → Снимки / hosts / DNS / IFEO / аудит / GPU…**.

### Снимки системы

Сохранение и загрузка JSON-эталона процессов, служб, Run/RunOnce и Startup folders.
Задания планировщика включаются отдельно. Сравнение показывает добавленные,
удалённые и изменённые элементы с учётом доступности разделов.

Фильтр новых EXE сравнивает путь, имя и пользователя, а не PID и не содержимое файла.
Перезапуск известного EXE не считается новой программой. Подмена файла по тому же
пути этим сравнением не выявляется. Эталон не признаётся заведомо чистым.
Снимок не атомарный и может быть частичным из-за прав доступа.

### hosts / DNS / IFEO

Read-only наблюдение, отчёт изменений и ручной экспорт. Изменения не блокируются,
ответственный процесс не устанавливается, IFEO автоматически не исправляется.
DNS могут легитимно менять DHCP/VPN. IFEO охватывает ограниченный список инструментов,
а DNS-проверка не является полным анализом DoH/NRPT и всех политик разрешения имён.

### Windows / Sysmon

Просмотр существующих событий за последние 10 минут, до 200 записей, с опциональным
обновлением. Sysmon отдельно устанавливается и настраивается администратором;
Security audit также может быть выключен или недоступен.

Это не перехват каждого VirtualAllocEx/WriteProcessMemory/GetAsyncKeyState.
Пустой журнал или ошибка чтения не означают отсутствие опасной активности.
Нажатия клавиш и содержимое буфера обмена не записываются.

### NVIDIA GPU

Доступные через установленную NVML нагрузка, температура и мощность; история
60 измерений первой GPU, остальные устройства — текстовый снимок. Нет установки
или загрузки драйверов. Недоступный датчик обозначается как н/д, а не нулём.

CPU/AMD/Intel power/temp без аппаратного провайдера не поддерживаются.
Тепловая инерция и падение нагрузки не доказывают скрытый майнинг;
атрибуция GPU-нагрузки по процессам не выполняется.

## Карантин и опасные действия

Выберите процесс → **Инструменты → Карантин выбранного EXE**.
После подтверждения сначала создаётся ZIP-контейнер `.vir` с образцом и метаданными,
проверяются CRC/SHA-256, затем процесс завершается и исходный EXE удаляется без корзины.
При отказе остановки или удаления контейнер сохраняется, но источник может остаться.

Это не переименование сырого PE, но также **не VM/sandbox/шифрование**:
контейнер можно извлечь, а образец — запустить. Автоматического восстановления
и запуска нет. Не извлекайте и не запускайте образцы на рабочей системе.

Завершение дерева — снимок, не атомарная остановка всех будущих потомков.
Suspend может удерживать locks и не останавливает другие процессы, драйверы
или уже отправленный I/O. Отдельные команды позволяют удалить EXE сразу или
поставить его на удаление при перезагрузке; отмены pending delete из GUI нет.

Windows/self/runtime, критические имена, PID/create_time и перенаправления проверяются,
но внешние гонки не исключены. ACL и защитные механизмы Windows не обходятся.
Для исследования malware используйте отдельную изолированную лабораторию.

## Режимы запуска и отзывчивость

В меню **Запуск** включается случайное имя при следующем запуске того же EXE.
Закройте и снова откройте программу; отдельный Random.exe не требуется.
Настройка хранится в `launch.ini`, временная копия интерпретатора удаляется после выхода.
Копия сохраняет hash; случайное имя не защищает от TerminateProcess.

Модель процессов обновляется без полного reset. Metadata кешируется до 15 с,
CPU/RSS обновляются по выбранному интервалу. Autosort ограничен пятью секундами;
щелчок заголовка сортирует сразу. Фоновые подписи включаются отдельно и по умолчанию
выключены. Системные API и число процессов влияют на нагрузку.

Ctrl+F — поиск, Ctrl+S — CSV, F5 — обновление системных вкладок.

## Что не реализовано

Нет kernel anti-kill/PPL, случайного hash, полного WinAPI trace, надёжного
перечисления всех keylogger/clipboard hooks, IFEO write-protection и универсального
детектора майнеров. Программа не является устойчивым к kernel-rootkit источником истины.

Версия 0.3.0 не содержит отдельной вкладки «Расширенный анализ», перебора PID,
сверки LOLDrivers, carving строк, COM/pipes inventory, анализа скрытых окон,
массовой экстренной приостановки или ransomware-блокировки.

## Приватность и данные

Работа локальная. VirusTotal — только явный запрос SHA-256 с ключом в памяти сеанса,
без upload файла и без редиректов с ключом. Запрос раскрывает сервису интерес к хешу.
Не отправляйте API-ключ разработчику и не добавляйте его в репозиторий.
Другие проверки не отправляют память и снимки в сеть.

Папка данных: `%LOCALAPPDATA%\OpenTaskMonitor`. В ней находятся логи, instance.lock,
launch.ini, packages, quarantine и резервные копии автозагрузки.
JSON-снимки сохраняются в выбранное пользователем место.

**Не удаляйте `startup-backup.json`, пока записи Run/RunOnce отключены.** Удаление
программы не включает их обратно. Восстановление не перезаписывает отличающуюся запись.
Старые кеши и незавершённые `.staging-*` автоматически не удаляются: очищайте только
packages после закрытия всех версий, не затрагивая резервные копии и карантин.

Логи, командные строки, пути, аккаунты, handles и отчёты могут содержать приватные
сведения. Проверяйте их перед публикацией. Карантин и JSON не шифруются и не защищены
от изменения пользователем/администратором. Не запускайте подменённый кеш или EXE
с повышенными правами.

## Исходники и сборка

В GitHub **Code** размещается содержимое source ZIP, включая `.github`; готовые
portable ZIP/EXE и отдельный changelog — в **Releases**. Не коммитьте runtime/build/.venv.

В workflow версии 0.3.0 **Build Windows app** создаются source и portable ZIP
с контрольными суммами; по тегу `v*` готовится черновик релиза. Отдельный changelog
прикладывается к релизу дополнительно: его автоматическая выдача этим workflow
версии 0.3.0 не предусмотрена. Проверяйте сборки перед публикацией.

Для разработчика: Python 3.11+, MinGW-w64; на Linux Wine/Xvfb для smoke tests.
Для запуска готового EXE эти инструменты не нужны.

```bash
python -m pip install -e ".[dev]"
python -m ruff check .
QT_QPA_PLATFORM=offscreen python -m pytest -q
python scripts/build_singlefile.py
python scripts/build_source_release.py
```

Runtime: CPython Embedded 3.12.10, PySide6/Shiboken 6.8.3, psutil 7.2.2,
MIT miniz 3.0.2. Сборочные входы закреплены SHA-256; исходные vendor binaries не изменяются.
Legacy folder/installer workflow сохранён как отдельный ручной вариант; публичный
portable — один EXE, без необходимости локальной сборки у пользователя.
