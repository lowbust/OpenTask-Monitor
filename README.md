# OpenTask Monitor 0.3.0

Независимый open-source диспетчер процессов и инструмент расследования для
**Windows 10/11 x64**. Собственный код — MIT. Python / PySide6 / psutil.
Не связан с AnVir; не антивирус, не средство гарантированной изоляции malware.

## Исходники и релиз — отдельно

- **opentask-monitor-0.3.0-source.zip** — только исходный проект для GitHub:
  Python/C, ресурсы, MIT, тесты, workflow, сборочные скрипты и MIT miniz.
- **OpenTaskMonitor-0.3.0-windows-x64-portable.zip** — **внутри ровно один файл:
  OpenTaskMonitor.exe**. Никаких исходников, папки runtime или сборочных скриптов рядом.

Распакуйте EXE в обычную папку и запустите. Python, pip, установщик и интернет
для подготовки приложения не нужны. Копировать на другой ПК нужно только EXE.

### Что означает «один EXE»

Зависимости сжаты внутри EXE. **При первом запуске этой сборки** native код без
PowerShell/shell/network распакует их в
`%LOCALAPPDATA%\OpenTaskMonitor\packages\<версия-хеш>` и покажет окно подготовки.
Поэтому первый запуск дольше и требует несколько сотен МБ свободного места.
Следующие запуски используют готовый кеш. Рядом с EXE ничего не создаётся.
Это однофайловое распространение, **не запуск без файлов на диске**.

Лицензии, notices и BUILD-INFO.json сохранены внутри поставки и доступны после
запуска через **«Справка → Лицензии и сведения о сборке…»**. DLL в кеше динамические
и могут быть заменены совместимыми модифицированными версиями; нет DRM/проверки
подписи наших зависимостей, запрещающей такую замену. Исходники и скрипты сборки
поставляются отдельно. Перед собственным бинарным релизом нужен license audit.

Обычный и случайный режим — в **том же EXE**. «Запуск → Случайное имя при следующем
запуске» → закройте → откройте EXE. Для обычного режима снимите флажок и повторите.
Настройка `%LOCALAPPDATA%\OpenTaskMonitor\launch.ini`. В случайном режиме создаётся
временная копия интерпретатора внутри кеша, удаляемая после выхода. Это не защита
от malware/завершения/AV. Отдельного Random.exe в релизе нет.

Кеши старых сборок не удаляются автоматически: так не затрагиваются запущенные
старые версии и заменённые пользователем LGPL DLL. После закрытия всех версий
можно удалить **только packages** для очистки кешей; они восстановятся из EXE.
После отменённой подготовки может остаться `.staging-*` внутри packages — его
можно удалить после закрытия приложения. **Не удаляйте startup-backup.json**:
это резервные копии отключённой Run/RunOnce, удаление программы их не включает.

## Для GitHub

В **Code** загрузите содержимое исходного архива. В **Releases** прикрепите
portable ZIP с единственным EXE (или извлечённый EXE). Не коммитьте готовый EXE,
runtime, .venv и build в git-историю. GitHub сам предлагает исходники у релиза,
но наш отдельный source ZIP также доступен для воспроизводимой сборки.

**Actions → Build Windows app → Run workflow** создаёт пару архивов
«source + one-EXE portable» и SHA256SUMS.txt. Artifact: **OpenTaskMonitor-release**.
По тегам `v*` готовится черновик GitHub Release. Перед публикацией проверьте сборку.
Альтернативный старый folder/installer workflow — только manual, не основной формат.

## Новое в 0.3.0: анализ, не антивирусная защита

- **Анализ процесса → Память / потоки**: read-only сравнение исполняемых секций
  главного PE-образа с EXE, учёт ASLR relocations/IAT, private executable регионы,
  адреса старта перечисленных потоков. Изолированный helper, максимум 15 секунд.
  JIT/hooks/антивирус могут давать легитимные отличия; это не детектор всех hollowing.
- **Анализ → Права токена**: Token Privileges, выделение включённых чувствительных
  прав, elevation/integrity. Право не включается и не отключается, злоупотребление
  по одному списку автоматически не устанавливается.
- **Приоритет 0–100** с объяснением в tooltip/CSV. Строки ≥60 красные и могут
  закрепляться сверху. Это баллы для ручной проверки, не вероятность malware.
  Неизвестная подпись/public IP сами по себе баллов не получают.
- **Инструменты → Снимки / hosts / DNS / IFEO / аудит / GPU…**: JSON-эталон
  процессов/служб/Run/Startup, optional задания, сравнение изменений и фильтр
  только новых EXE. Эталон не считается заведомо чистым.
- **Карантин** после подтверждения: проверенный не-PE ZIP-контейнер `.vir`, затем
  завершение процесса и обычное удаление исходника. Не sandbox/VM и не шифрование;
  файл можно извлечь, поэтому не запускайте образцы на рабочем компьютере.
- **hosts/DNS/IFEO**: optional read-only наблюдение, отчёт изменений, экспорт.
  Это не запрет записи и не установление виновного процесса. IFEO не исправляется.
- **Windows/Sysmon**: просмотр существующих событий, optional обновление каждые 10 с.
  Требуется отдельно настроенный аудит/Sysmon. Это **не** монитор каждого
  VirtualAllocEx/WriteProcessMemory/GetAsyncKeyState. Клавиши/clipboard не читаются.
- **NVIDIA NVML**: доступные датчики нагрузки/температуры/ватт и 60 отсчётов истории
  первой GPU. Наблюдение тепловой инерции не объявляется скрытым майнером.
  CPU/AMD/Intel power/temp без провайдера недоступны, фиктивных значений нет.

**Не реализованы:** kernel anti-kill/Protected Process, случайный hash подписанного
интерпретатора, полная трассировка WinAPI, надёжное перечисление всех keylogger/
clipboard hooks, IFEO write-protection, универсальный детектор майнеров.
Случайное имя сохранено; копия имеет прежний hash и не защищает от TerminateProcess.
Новые мониторы выключены по умолчанию; тяжёлые проверки выполняются в фоне по запросу.
Подробная матрица возможностей/пределов: **docs/SECURITY-ANALYSIS.md**.

## Однофайловая поставка (с 0.2.2)

- Публичный portable ZIP теперь содержит только один OpenTaskMonitor.exe.
- Встроенный offline runtime, первый запуск с прогрессом и кеш для следующих запусков.
- Native extractor: MIT miniz 3.0.2, чтение ZIP/CRC, ограничение путей/размера,
  marker и переименование полностью подготовленного staging в конечный кеш.
- Оба режима и функции 0.2.0/0.2.1 сохранены.
- Меню открытия лицензий/BUILD-INFO; источник и бинарный релиз пакуются отдельно.
- Сам запускающий EXE защищён от функции удаления файла диспетчера.

## Что изменилось с 0.1.0

### Плавность

- Вместо полного reset модели каждый тик — точечные insert/remove/dataChanged.
  Выделение и индексы не сбрасываются при обновлении CPU/RSS.
- Автосортировка не пересчитывается на каждое изменение ячейки: раз в 5 секунд.
  Щелчок заголовка сортирует сразу; поиск обновляется при вводе.
- Имя/путь/пользователь/PPID/потоки/статус кешируются до 15 секунд.
  CPU/RSS — каждый выбранный интервал; новые процессы читаются сразу.
- Дорогие DLL, handles, VT и сеть — отдельные фоновые операции по запросу.
- Фоновые подписи по умолчанию выключены: можно включить в меню «Инструменты».
  Они идут в отдельном ограниченном worker, результаты применяются пакетно.
- Внизу видно время сбора данных. Это не гарантия отсутствия лагов на любом ПК:
  системные API, защитное ПО и число процессов влияют на нагрузку.

### Анализ выбранного процесса

Выберите процесс → **«Анализ…»** или контекстное меню.

| Возможность | Реализация / границы |
|---|---|
| Authenticode | Offline WinVerifyTrust, встроенные + Windows catalog подписи; издатель из сертификата |
| Подсветка | Столбец «Проверка» и цвет имени: необычный путь, ошибки подписи, родитель shell |
| VirusTotal API v3 | По кнопке, только SHA-256, без upload файла, ключ только в RAM текущего сеанса |
| Process Tree | Дерево-снимок с PPID/create_time, защита от ложного родителя при переиспользовании PID |
| Двойники системных имён | svchost/lsass/csrss/services и другие вне штатных System32/SysWOW64, explorer вне Windows |
| Сеть | IPv4/IPv6 TCP/UDP, IP/порты, ручное или 3-секундное обновление выбранного процесса |
| Разрыв соединения | SetTcpEntry для IPv4 TCP; нужен admin, не UDP/IPv6; процесс может переподключиться |
| DLL | Read-only snapshot memory_maps, фильтр .dll; DLL в памяти не доказывает injection |
| Handles | File/Key через NT API в отдельном subprocess; до 512 записей, лимит 10 секунд |
| Kill Process Tree | Снимок потомков, preflight критических процессов, проверка create_time перед каждой командой |
| Suspend/resume | Приостановка/возобновление потоков; не делает процесс или систему безопасными |
| Удаление EXE | Подтверждение, завершение и обычный unlink без корзины, либо MoveFileEx при reboot |
| Автозагрузка | Run + RunOnce HKCU/HKLM 32/64 с восстановимым отключением; Startup folders — просмотр |
| Task Scheduler | Read-only список, включая доступные hidden tasks; PowerShell Get-ScheduledTask |
| Службы | Список, start/stop через sc.exe; редактирование типа запуска не реализовано |

## Важное: признаки ≠ диагноз

- Подпись без онлайн-revocation не проверяет отзыв сертификата в интернете.
  Валидная доверенная подпись не доказывает отсутствие malware.
- Отсутствие подписи не делает программу вирусом. Наш собственный launcher
  не подписан; он ожидаемо может подсвечиваться как неподписанный.
- Shell из IDE/службы/скрипта может быть совершенно легитимным. Родитель — подсказка.
- Проверяется файл на диске, не содержимое памяти и не digital signature памяти.
- VirusTotal возвращает существующий отчёт по хешу. 404 — файла в базе нет,
  upload не выполняется. 0 detections не гарантирует безопасность.
- Наличие file/key handle не означает, что объект заблокирован или изменяется.
  Список частичный: NT API недокументирован, отдельные запросы могут зависать,
  поэтому helper принудительно ограничен по времени. Основной процесс не виснет.
- Kill tree не атомарен; новые потомки/внешние watchdog могут перезапускать процессы.
- Suspend не останавливает другой процесс, драйвер или уже отправленный I/O.
  Не исследуйте реальное вредоносное ПО на рабочей системе.

## Где кнопки

- **Анализ… → Подпись / VirusTotal**, **Process Tree**, **DLL**, **Сеть**, **Дескрипторы**.
- **Инструменты → Фоновые подписи (offline)** — проверки списка, столбец «Проверка».
  Путь и проверка находятся справа в широкой таблице: доступна горизонтальная прокрутка.
- **Инструменты → Завершить дерево**, **Завершить и удалить**, **Удалить при перезагрузке**.
- **Инструменты → Забыть API-ключ VirusTotal** — удалить ключ из памяти сеанса.
- **Автозагрузка → Планировщик задач…** — отдельный список заданий.
- Ctrl+F — поиск; Ctrl+S — CSV видимых процессов; F5 — обновление системных вкладок.
- Пауза сверху — пауза мониторинга, не самих процессов.

## VirusTotal и приватность

Получите свой ключ в аккаунте VirusTotal и введите в password-диалог приложения.
**Не присылайте ключ разработчику и не добавляйте в GitHub.** Он не записывается
в настройки или логи. Только по явному подтверждению отправляется GET-запрос
на `https://www.virustotal.com/api/v3/files/<sha256>` с ключом в HTTPS header.
Redirect с ключом запрещён. Файл, путь и cmdline не отправляются.
Сам запрос раскрывает VT интерес к конкретному хешу. Учитывайте условия сервиса
и лимиты тарифа: локальная пауза 16 секунд — не обещание достаточной квоты.
Остальные проверки приложения не требуют сетевого API; VT можно не использовать.

## Безопасность опасных операций

Изменения требуют подтверждения с default «Нет». Есть denylist критических имён,
собственного PID/0/4 и повторная проверка create_time. Это страховка от ошибки,
не security boundary. Безопасность удаления проверяется по пути, а не по имени:
файлы Windows, собственного runtime и исходников программы запрещены, symlink/
перенаправления отклоняются. ACL/защита Windows не обходятся; удаление может не
сработать, хотя процесс уже завершён. Отмена pending delete из GUI не реализована.
На момент удаления остаются TOCTOU-гонки ОС: это не атомарная антивирусная операция.

**Kernel-mode драйвера нет.** Его нельзя безопасно заменить user-mode трюком.
Нужны отдельный WDK-проект, разработка под актуальные Windows/HVCI, подпись,
проверка с Driver Verifier/VM и модель угроз. Фиктивный/неподписанный драйвер не
включён. Диспетчер может быть завершён другим процессом с достаточными правами.

## Данные и автозагрузка

`%LOCALAPPDATA%\OpenTaskMonitor`: `startup-backup.json`, логи, instance.lock, packages и quarantine. JSON-снимки сохраняются в выбранный файл.
Не удаляйте backup, пока записи Run/RunOnce отключены. Удаление программы их
не восстанавливает! Включение не перезаписывает существующую отличающуюся запись.
Копия пишется до удаления значения; после сбоя оригинал и копия могут остаться
одновременно. Если команды совпадают, включите копию, чтобы убрать дубль.
Размер окна/интервал: HKCU\Software\OpenTaskMonitor\OpenTaskMonitor (QSettings).
Ключ VT там не хранится. Cmdline, пути и handles могут содержать приватные данные.
Проверяйте содержимое, прежде чем делиться скриншотами/логами/CSV.

Task Scheduler и Startup folders — только просмотр; задачи/службы не удаляются,
тип запуска службы не меняется. Это не полный Autoruns: WMI subscriptions,
AppInit, драйверы и прочие persistence не перечисляются. IFEO наблюдается только для ограниченного списка инструментов, не полный Autoruns.

## Исходники / GitHub / сборка

В GitHub загрузите **содержимое исходного архива**, включая `.github`, но не
portable ZIP, `.venv`, runtime, логи и build. Публичный репозиторий + MIT позволяют
изменять и распространять собственный код; Qt/Python имеют отдельные лицензии.
Готовый portable ZIP выкладывайте в Releases, не в исходное git-дерево.

Разработка на Windows, Python 3.11–3.13 x64:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m opentask
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
```

Точная воспроизводимая поставка — `python scripts/build_singlefile.py`
на Linux с MinGW-w64/Python/pip (или Windows с MinGW на PATH). Pins/SHA-256 в скрипте.
Выход: `release/OpenTaskMonitor-0.3.0-windows-x64-portable.zip` (один EXE).
Qt/PySide6 6.8.3, CPython Embedded 3.12.10, psutil 7.2.2. Библиотеки динамические,
доступны для замены совместимыми версиями, upstream binaries не модифицируются.
Альтернативный workflow **Legacy folder app and installer (manual)** использует PyInstaller/Inno Setup,
другую структуру (`_internal`) и не выдаётся за проверенную здесь сборку Setup.
Старый папочный builder остаётся внутренним шагом подготовки runtime; публичный релиз — single-file.

Проверки и ограничения: **VERIFICATION.md**, **docs/TESTING.md**, **SECURITY.md**.
ПО alpha, без гарантий; перед production нужны тесты реальной Windows и
проверка актуальности зависимостей. Нельзя обещать безопасность работы с вирусами.
